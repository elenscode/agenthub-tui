# Linux 파일 변경과 복구

- 실행 사용자의 권한으로 현재 프로젝트와 전역 설정에 접근합니다. 지원 버전, 관리형 정책, 경로와 파일 형식을 확인한 뒤 MCP·Skill의 변경안을 만듭니다.
- 승인된 변경은 백업 잠금을 잡고 원본과 변경안을 암호화한 후 디스크에서 다시 읽어 검증합니다. 적용 직전에 복사 원본과 대상을 다시 검사합니다. 다른 프로그램이 수정한 파일과 충돌하면 새 변경안이 필요합니다.
- Linux 백업은 XChaCha20-Poly1305로 암호화합니다. 첫 승인 시 난수 키를 상태 디렉터리의 `keys/backup.key`에 생성합니다. 키 디렉터리와 파일의 기본 권한은 각각 0700, 0600입니다. 기존 스냅샷이 있을 때 키가 사라지면 복구를 위해 원래 키가 필요합니다. 같은 계정 권한으로 실행되는 프로그램은 이 키를 읽을 수 있습니다.
- 파일 교체 시 모드 비트를 보존하고, 새 파일을 만들 때는 경로 충돌을 검사합니다. 심볼릭 링크나 하드링크로 연결된 파일은 수정 대상에서 제외합니다. 여러 파일 중 일부만 적용된 상태에서 실패하면 적용 순서의 역순으로 복구하고, 그사이 다른 프로그램이 바꾼 항목은 부분 복구로 보고합니다.
- 본문·Diff의 인증 필드를 마스킹하고 진단 내보내기에는 집계값과 CLI 버전을 기록합니다. MCP 수동 진단은 사용자 승인 후 초기화와 도구 목록 조회를 수행합니다. 12초 제한 시간과 출력 크기 제한을 적용합니다.
- 변경 후 백업을 최대 30개, 30일 기준으로 정리합니다. 파일당 2 MiB, 스냅샷 대상 폴더당 8 MiB·2,048개 항목까지 처리합니다.
